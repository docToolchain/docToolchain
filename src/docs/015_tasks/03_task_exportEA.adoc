== exportEA

include::../_feedback.adoc[]

=== About This Task

By default, no special configuration is necessary.
However, several optional parameter configurations are available to support a project and packages to be used for export.
These parameters can be used independently from one another.
A sample of how to edit your projects' Config.groovy is provided in the 'Config.groovy' of the docToolchain project itself.

=== Important

Currently this feature is WINDOWS-only. See https://github.com/docToolchain/docToolchain/issues/231[this related issue].

[IMPORTANT]
====
*Database Connection Limitation*

The `connection` parameter for database connections (e.g., `DBType=1;Connect=Provider=...`) is currently **not fully supported** in the VBScript implementation. 

The VBScript uses the `Repository.OpenFile()` method which is designed for file paths (`.eap`, `.eapx`, `.qea`, `.qeax` files), not database connection strings. Using a connection string will result in a COM error.

*Workaround:* Use file-based Enterprise Architect project files (`.eap`, `.eapx`, `.qea`, or `.qeax`) instead of database connections. Place these files in your project's `searchPath` directory, and the exportEA task will automatically find and process them.
====

=== The Optional Parameter Configurations

==== connection
Sets the connection to a specific Enterprise Architect project file or database.

[WARNING]
====
*Important:* Database connection strings (using `DBType=1;Connect=Provider=...` format) are currently **not supported** due to VBScript API limitations.

**Recommended approach:** Use file-based EA project files instead.
====

*Usage:*

* **File-based (Recommended):** Comment out the `connection` parameter to use all project files found in the `searchPath` directory
* **Database connection:** Currently not supported - will cause errors like `0x80131700`

*Example (file-based approach):*
[source,groovy]
----
exportEA.with {
    // Leave connection commented out to search for .eap/.eapx files
    // connection = ""  // <- Keep this commented out
    searchPath = "src/docs/"  // Directory to search for EA project files
    exportPath = "src/docs/images/ea/"
    packageFilter = ["{YOUR-PACKAGE-GUID}"]
}
----

==== packageFilter
Add one or multiple packageGUIDs to be used for export. All packages are analysed, if no packageFilter is set.

===== diagramFilter
On top of filtering via packages you have the chance to filter for certain diagrams inside the packages defined via <<packageFilter>>.

You can define the tag that is used to filter the diagrams. Only diagrams with this tag in the are exported.

To set the tags you can use the diagram properties in Enterprise Architect.
The tags are stored in the https://sparxsystems.com/enterprise_architect_user_guide/17.0/add-ins___scripting/diagram2.html['Stereotype'] field of the diagram properties.

Default: None +
Example: diagramFilter = "myProject1, myProject2"

[NOTE]
====
Using the `diagram.Stereotype` field is a workaround to filter for diagrams.
The field is not intended to be used for filtering purposes.
But due to limitations of what is made available via the API, this is the only way to filter for diagrams.

If in the future the API provides a way to filter for diagrams, this workaround will be removed.
====

==== exportPath
Relative path to base 'docDir' to which the diagrams and notes are to be exported.

Default: "src/docs". +
Example: docDir = 'D:\work\mydoc\' ; exportPath = 'src/pdocs' ;

Images will be exported to 'D:\work\mydoc\src\pdocs\images\ea',
Notes will be exported to 'D:\work\mydoc\src\pdocs\ea',

==== searchPath
Relative path to base 'docDir', in which Enterprise Architect project files are searched.

Default: "src/docs". +
Example: docDir = 'D:\work\mydoc\' ; exportPath = 'src/projects' ;

Lookup for eap and eapx files starts in 'D:\work\mydoc\src\projects' and goes down the folder structure.
*Note*: In case parameter 'connection' is already defined, the searchPath value is also used.
exportEA starts opening the database parameter 'connection' first then looks for
further project files either in the searchPath (if set) or in the docDir folder of the project.

==== glossaryAsciiDocFormat
Whether the EA project glossary is exported depends on this parameter.
If not set or an empty string, no glossary is exported.
The glossaryAsciiDocFormat string is used to format each glossary entry in a
certain AsciiDoc format.

The following placeholders are defined for the format string: ID, TERM, MEANING, TYPE.
One or more can be used by the output format. For example:

A valid output format is to include the glossary as a flat list.
The file can be included where needed in the documentation.
....
glossaryAsciiDocFormat = "TERM:: MEANING"
....
Other format strings can be used to include it as a table row.
The glossary terms are sorted in alphabetical order.

==== glossaryTypes
This parameter is used in case a glossaryAsciiDocFormat is defined, otherwise it
is not evaluated. It's used to filter for certain types.
If the glossaryTypes list is empty, all entries will be used.
For example:

glossaryTypes = ["Business", "Technical"]

==== diagramAttributes
If set, the string is used to create and store diagram attributes to be included in the document alongside a diagram.
These placeholders are defined and populated with the diagram attributes, if used in the
diagramAttributes string:

`%DIAGRAM_AUTHOR%`, +
`%DIAGRAM_CREATED%`, +
`%DIAGRAM_GUID%`, +
`%DIAGRAM_MODIFIED%`, +
`%DIAGRAM_NAME%`, +
`%DIAGRAM_NOTES%`, +
`%DIAGRAM_DIAGRAM_TYPE%`, +
`%DIAGRAM_VERSION%`, +
`%NEWLINE%` +

Example: diagramAttributes = "Last modification: %DIAGRAM_MODIFIED%%NEWLINE%Version: %DIAGRAM_VERSION%"

You can add the string %NEWLINE% where a line break will be added.
The resulting text is stored next to the diagram image using the same path and file name, but a different file extension (.ad). This can be included in the document if required.
If diagramAttributes is not set or an empty string, no file is written.

==== imageFormat
If set, the set image format is used to export the diagrams.
Default is set to ".png".

Please check your Enterprise Architect version which formats are supported.

==== additionalOptions
This parameter is used to define the specific behavior of the export. Currently, these mutually exclusive options are supported:

* `KeepFirstDiagram` +
If diagrams are not uniquely named, the last diagram will be saved. If you want to prevent diagrams from being overwritten, add this parameter to additionalOptions.
* `append_GUID` +
Append the diagram GUID to the diagram name to guarantee a unique name.
* `prepend_GUID` +
Prepend the diagram GUID before the diagram name guarantee a unique name.
* `use_GUID` +
Ignore the diagram name and only use the GUID as diagram name.

==== verbose output
If set to bigger than 0, the exportEA task will output additional information about the export process.

For example:

verboseLevel = 1

=== Glossary export
By setting the glossaryAsciiDocFormat, the glossary terms stored in the EA project
will be exported into a folder named 'glossary' below the configured exportPath.
In case multiple EA projects are found for export, one glossary per project is
exported - each named using the project's GUID plus extension '.ad'.

Each individual file will be filtered (see glossaryTypes) and sorted in alphabetical order.
In addition, a global glossary is created by using all single glossary files.
This global file is named 'glossary.ad' and is also placed in the glossary folder.
The global glossary is also filtered and sorted.
If there is only one EA project, only the global glossary is written.

=== Troubleshooting

==== Error: `exportEAP.vbs(...) (null): 0x80131700`

*Symptoms:*

* Task `:exportEA FAILED`
* Error message: `Script 'C:\...\scripts\exportEA.gradle' line: 132`
* VBScript error: `exportEAP.vbs(M15, 3) (null): 0x80131700`

*Cause:*

This error occurs when attempting to use a database connection string in the `connection` parameter. The VBScript implementation uses `Repository.OpenFile()` which only supports file paths, not database connection strings.

*Solution:*

1. **Remove or comment out the `connection` parameter:**
+
[source,groovy]
----
exportEA.with {
    // connection = "DBType=1;Connect=Provider=..."  // <- Comment this out
    searchPath = "src/docs/"
    exportPath = "src/docs/images/ea/"
}
----

2. **Place your EA project files in the searchPath:**
+
Copy your `.eap`, `.eapx`, `.qea`, or `.qeax` files to the directory specified in `searchPath` (default: `src/docs/`)

3. **Run the task again:**
+
[source,bash]
----
./dtcw local exportEA
----

==== Error: No EA project files found

*Symptoms:*

* Task completes but no diagrams are exported
* Message: "looking for .eap(x) and .qea(x) files in ..."

*Solution:*

1. Verify that your EA project files (`.eap`, `.eapx`, `.qea`, or `.qeax`) are in the `searchPath` directory
2. Check that file names don't start with underscore `_` (these are skipped as replication files)
3. Ensure the `searchPath` is configured correctly in your config file

==== Error: Enterprise Architect is not installed

*Symptoms:*

* Error: "Cannot create object 'EA.App'"

*Solution:*

Enterprise Architect must be installed on the Windows machine where you're running the exportEA task. This task uses EA's COM automation interface which requires a local installation.

==== General Tips

* *Use verbose output:* Set `verboseLevel = 1` to see detailed processing information
* *Check file permissions:* Ensure the export directories have write permissions
* *Verify EA version:* Some features may require specific EA versions
* *Use file-based projects:* For best compatibility, always use `.eap` or `.eapx` files instead of database connections
